================================================================================
1. PURPOSE AND SCOPE
================================================================================

Module 4 bootstraps an empty graph with foundational knowledge and provides
the curated ETL path that loads the GCIDE corpus into it. It has two halves:

1. Hardcoded upper ontology: top-level concepts, structural relations, the
   type hierarchy, domain/range expectations, and reality rules. Permanent,
   small, deterministic.
2. GCIDE ETL: a streaming parser and loader that maps the 26 CIDE.* files
   (131,569 headwords, ~61 MB) into lexical Word nodes and semantic
   Sense/Concept nodes with IS_A, SYNONYM, ANTONYM, IS_NAMED, HAS_POS, and
   related structural links.

Module 4 is responsible for:

- Base concepts such as Entity, Event, Time, Location, and other top-level
  categories.
- Structural relationships such as IS_A, PART_OF, CAUSES, HAS_PROPERTY,
  PARTICIPATED_IN, HAS_TIME, HAS_LOCATION, and IS_NAMED.
- Type hierarchies and domain/range expectations for relationships.
- Rules that distinguish real, fictional, conditional, and hypothetical
  knowledge.
- Startup population routines for a new graph.
- Curated loading from reputable sources through an ETL path.
- Giving new facts enough structure to attach to the graph without hardcoding
  specific world facts.

Module 4 is NOT responsible for:

- Statistical NLP, machine learning, embeddings, or external packages.
- Genus-differentia mining of definition prose (deferred).
- Enforcing selectional restrictions inside the matcher (advisory only here).
- Languages other than English.
- Background persistence or an external graph database.
- Treating dictionary prose as ground truth; the corpus is historical.

================================================================================
2. ACCEPTED DESIGN DECISIONS
================================================================================

1. Native C# only. No external libraries.

2. Ontology relations occupy the reserved 1-999 ID range
   (RelationRegistry.LastReservedOntologyId = 999) with fixed, hardcoded IDs
   so they are stable across runs and match the Module 3 reservation.

3. Direct graph population, not ReasoningEngine.Ingest. Structured markup is
   not natural language; bypassing trust and matching keeps a 131k-entry load
   tractable and deterministic. Permanent nodes and links are written through
   LRD_Core.AddExistingNode and LRD_Core.AddDirectedConnection.

4. Lexical/semantic separation (README rule). One Lexeme node per headword
   form, one Sense node per definition, joined by HAS_SENSE and IS_NAMED.

5. Idempotent load. Re-running the loader reuses existing permanent nodes
   (matched by label and type) and skips duplicate links.

6. On-demand with persistence. OntologyLoader.Build produces an in-memory
   graph, then exports a versioned .lrdlog; later runs import it through the
   existing Tools path. Startup stays fast.

7. GCIDE is read-only input, kept as a sibling gcide-0.54/ folder. Derived
   data is separate. The GPLv3 notice is preserved.

================================================================================
6. GCIDE CORPUS FORMAT
================================================================================

- 26 files CIDE.A through CIDE.Z, ~61 MB, SGML-like tags. Paragraphs are
  <p>...</p> (232,491 total; 131,569 contain <hw>).

- Entry paragraph shape:
  <p><ent>dog</ent><br/>
  <hw>dog</hw> <pos>n.</pos> <sn>1.</sn> <def>...</def><br/>
  <syn>...</syn> [<source>...</source>]</p>

- Tags to consume: <ent> (ASCII index headword), <hw> (accented headword),
  <pos> (part of speech), <sn> (sense number), <def> (definition), <syn>,
  <altname>, <asp>/<altsp>, <ant> (antonym), <stype> (subtypes of headword),
  <isa> (supertype of headword), <fld> (field), <source>, taxonomy tags
  (<kingdom> through <gen>), and relational tags (<part>/<partof>,
  <member>/<membof>, <causes>/<causedby>, <produces>/<prodby>,
  <uses>/<usedby>, <stage>/<stageof>).

- Observed semantic tag counts: <syn> 10,387; <altname> 7,937; <stype> 2,554;
  <ant> 1,084; <isa> 195. <pos> 144,521; <def> 179,781; <fld> 49,973.

- Special escapes to decode (webfont.txt): \'xx hex codes (e.g. \'94 = o
  with diaeresis) and <word/ entities; <br/ becomes a break or space. The
  parser must not misread <br/, <or/, <and/ as elements.

- <p> tags do not nest cleanly with <note> and <cs>; the reader must tolerate
  mismatches (per the GCIDE README and tagset.txt).

================================================================================
7. PIPELINE ALGORITHMS
================================================================================

7.1 Markup decoding
- Single pass replacing \'xx and <entity/ with Unicode; normalize whitespace;
  keep optional source spans.

7.2 Entry reading
- Stream each file, split on <p> and </p>, and emit an entry only when the
  block contains <hw>. GcideEntryReader.Read(path) yields lazily and never
  buffers the whole corpus.

7.3 Entry parsing
- Extract headword (<ent> preferred, else cleaned <hw>), POS list, and per
  sense {sn, def text, source, fld}. Collect relation targets: synonyms,
  altnames, antonyms, stype, isa, taxa, parts, and related tags. Resolve
  target phrases to headword keys (normalized, lowercased, spaces and hyphens
  unified).

7.4 Graph mapping
- Headword to Lexeme node; label is the normalized ASCII headword; aliases
  are the <hw> form and <asp> variants (deduped by Node.Add_Alias).
- Each sense to a Sense node (NodeTypes.Senses); label is a truncated or
  cleaned definition or a stable word#senseN key; definition text stored via
  DataPointer or label.
- Lexeme --has_sense--> Sense; Sense --is_named--> Lexeme;
  Lexeme --synonym--> Lexeme (symmetric, added both directions);
  Lexeme --antonym--> Lexeme (ID 2,000,000);
  Lexeme --is_a--> target for <isa> (the target is the supertype) and
  <stype> (the target is the subtype);
  Lexeme --has_pos--> POS node; Sense --has_field--> Field node.
- Unresolved relation targets are skipped by default (counted as
  diagnostics); GcideLoadOptions.ResolutionMode may instead create temporary
  placeholders.

7.5 Idempotence and merge
- Before creating, FindByLabel(label, type) and reuse an existing permanent
  node. AddDirectedConnection dedupes links through Web_Node.Add_Link.

================================================================================
8. LOADING STRATEGY
================================================================================

- Foundation load (UpperOntologyBootstrap.Populate): about 50 nodes and 80
  links; cheap and deterministic; gated by OntologyOptions.AutoSeedFoundation
  (default false per the on-demand decision, exposed as a Tools button).

- Corpus load (GcideCorpusLoader) is driven by GcideLoadOptions:
  - Subset: All, ByLetter(char), SemanticOnly (entries carrying any of
    stype/isa/ant/syn/altname), ByPartOfSpeech, MaxEntries(int).
  - MaxEntries cap, progress callback, and CancellationToken. The recommended
    default is SemanticOnly with a cap (fast demo); a full load is opt-in.

- Persist: after build, CoreLogExporter writes a versioned .lrdlog; later runs
  use CoreLogImporter through the existing Tools import. New node types, link
  classes, and ontology relations serialize through the existing
  TypeDefinitionLog.

- Persistence fix required: relax CoreLogImporter.cs:414-418 and
  RelationRegistry.TryRestore (RelationRegistry.cs:92-96) so ontology
  relations (1-999) can be exported and restored. Approach: register ontology
  relations first (populating ForwardLinkTypes and InverseLinkTypes), then have
  TryRestore and the importer accept an ID <= 999 only when it matches an
  already-registered ontology relation name; otherwise keep rejecting. Add
  RelationRegistry.RegisterOntologyRelation(id, name, inverseName) that
  bypasses the <= 999 guard.

================================================================================
9. DOMAIN/RANGE AND REALITY RULES
================================================================================

- OntologyValidator encodes a domain/range table for structural relations,
  for example:
    is_a:          Concept -> Concept
    has_time:      Event -> Time
    has_location:  Event or Entity -> Location
    has_property:  Entity -> Property
    is_named:      Concept -> Lexeme

- RealityRule: a concept's reality status is Real unless it is reachable under
  Fictional, Hypothetical, or Conditional through is_a or instance_of.
  Helpers: GetRealityStatus(node) and IsConsistent(link).

- These are advisory for now (tests and future matcher filtering). No
  enforcement in SubgraphMatcher in this module.

13. KNOWN LIMITATIONS
================================================================================

- Definitions are 1890s-era and occasionally inaccurate or offensive (per the
  GCIDE README); they are treated as historical lexical data, not truth.
- Only a fraction of entries carry explicit semantic tags, so the type
  hierarchy is sparse without genus-differentia mining (deferred).
- Domain/range and reality rules are advisory, not enforced in matching yet.
- A full-corpus load is memory and CPU heavy (roughly 300k nodes and 400k+
  links); the default is a curated subset.
- The persistence importer keeps 64 MB / 100k-node / 500k-link safety caps
  from Module 3, so a full-corpus .lrdlog needs a future cap change. Curated
  subsets, including the 2,000-entry default, fit comfortably.
- Multiword and phrase headwords resolve best-effort by normalized string
  match.
