Phase 8 adds three focused usability and language features after the Phase 7
integration baseline:

1. Gate the existing Tools button until core initialization succeeds.
   At the Phase 8 baseline, the Tools window was still a placeholder for
   Import, Export, and Visualizer. It must not open before Launch Core has
   initialized the graph.

2. Add configurable first-person speaker identity to ingestion.
   I/me/my/mine/myself and we/us/our/ours/ourselves resolve to one reusable
   speaker node. The label is configurable through NlpOptions and defaults to
   "User". Second-person pronouns remain unsupported.

3. Add subjectless command recognition to Ask.
   Commands beginning with output, print, respond, or reply are recognized when
   they are directed at the core and have no subject. Commands support a query
   target or a fixed target: facts, graph, conversation, summary, or node <id>.
   Commands are read-only: they do not mutate the graph, conversation turn,
   mentions, focus, or provenance. Missing or ambiguous targets produce a
   clarification question in the answer area.

5. FIRST-PERSON SPEAKER IDENTITY
================================================================================

Design:

- NlpOptions.FirstPersonSpeakerLabel defaults to "User".
- Blank labels fall back to "User".
- First-person pronouns resolve to one NodeTypes.Entities node with that label.
- The node is created lazily by normal ingestion, not by Ask.
- Both singular and plural first-person forms map to the configured speaker
  node. Reflexive first-person forms use the same node and remain subject to
  the existing self-loop guard.
- Second-person pronouns, indefinite pronouns, and unresolved third-person
  pronouns keep their current behavior.

Resolution order in EntityResolver:

1. If the argument is a first-person pronoun, resolve speaker identity.
2. If a cached speaker node ID exists for this resolver and still exists in the
   graph, reuse it.
3. Otherwise find NodeTypes.Entities nodes by the configured label.
4. One match: reuse it.
5. Multiple matches: return ambiguity and do not ingest.
6. No match: allocate a stable node ID through CreateNodeId and return it with
   IsPronoun = false. ChainBuilder creates the node during ingestion only.
7. Non-first-person pronouns continue through ConversationContext.

Acceptance:
- Ingesting "I work at Acme." creates or reuses the configured speaker node.
- No literal "I" or "we" node is created.
- Multiple first-person statements in one operation reuse one node.
- "Where do I work?" answers after speaker ingestion.
- A custom FirstPersonSpeakerLabel is honored.
- Asking before any speaker ingestion returns no-match without graph mutation.
- Second-person pronouns remain unsupported.

================================================================================
6. ASK COMMAND RECOGNITION
================================================================================

Recognition:

- Commands are recognized only in Ask, never in Ingest.
- Ignore leading punctuation and an optional "please".
- The first content word must be output, print, respond, or reply.
- The command has no subject before the verb.
- Optional separators after the verb: with, to, about, or colon punctuation.
- Command matching is lexical and case-insensitive; no Lexicon verbs are added.

Targets:

Fixed:
- facts, all facts, data, all data
- graph
- conversation, session
- summary
- node <guid>

Query:
- A remainder beginning with a wh-word or auxiliary is treated as a question.
- A remainder after an explicit with/to/about separator is treated as a query.
- Add a question mark when a question-like remainder lacks one.
- A remainder that is neither fixed nor question-like asks for clarification.

Clarification:
- Missing target: ask what to output and list supported targets.
- "node" without an ID: ask which node ID to show.
- Invalid or missing node: return no-match or clarification without guessing.
- A subject before the command verb means the input is not a command.

Execution:

- Refactor the normal Ask body into a private method with an
  updateConversation flag.
- Normal Ask begins a turn and updates focus/mentions as before.
- Commands do not begin a turn and do not update focus, mentions, turn index, or
  provenance.
- Query commands may read existing conversation context for pronoun resolution.
- Fixed targets read directly from LRD_Core and ConversationContext.
- Command output appears in Answer.Text and Answer.ShortAnswer so the existing
  NLP Workbench answer and summary display works without a new result pane.

Fixed-target formatting:

- facts: sorted directed links with source label, relation name, target label,
  and link class; truncate by MaxAnswerTextLength with a diagnostic.
- graph: node count, directed link count, and node-type counts.
- conversation: conversation ID, turn, focus, mention/provenance counts, and
  last subject/object/qualifier/answer node IDs.
- summary: graph summary plus conversation summary.
- node <guid>: label, type, lifetime, aliases, incoming links, and outgoing
  links; set AnswerNodeID when found.

Status mapping:
- Successful fixed or query command: NlpStatus.Answered.
- Missing or ambiguous target: NlpStatus.Ambiguous.
- Invalid node or no matching query result: NlpStatus.NoMatch or the existing
  query result status, as appropriate.
- NlpResult.Command records the recognized verb and target kind.

Acceptance:
- All four command verbs work.
- Query and fixed targets work.
- Commands work only through Ask.
- Commands are deterministic.
- Graph counts, conversation turn, mentions, focus, and provenance are unchanged.
- Clarification prompts appear in Answer.Text for incomplete commands.
