Status: Approved. Phase 3 parsing and NER complete.

Implementation constraint: Native C# with no external library dependencies.

================================================================================
1. PURPOSE AND SCOPE
================================================================================

Module 3 converts human language into temporary graph chains for Module 2 and
converts reasoning results back into readable answers.

Module 3 is responsible for:

- Sentence segmentation, tokenization, and text normalization.
- Part-of-speech tagging and lemmatization.
- Noun, verb, and prepositional phrase chunking.
- Named-entity detection and semantic type assignment.
- Subject-verb-object relation extraction.
- Copula, possession, coordination, and prepositional qualifier handling.
- Pronoun and conversation-context resolution.
- Text-to-chain ingestion through the Reasoning Engine.
- Question analysis and query-chain construction.
- Natural-language answer generation.
- Explicit diagnostics for unsupported, ambiguous, and no-match cases.

Module 3 is NOT responsible for:

- Statistical NLP, machine learning, embeddings, or external packages.
- Languages other than English in the initial implementation.
- Full dependency or constituency parsing.
- Branched graph matching; Module 3 emits linear chains only.
- Full event reification, temporal logic, or durable lexical storage.
- Upper-ontology rules, type hierarchies, or selectional restrictions.
- Persistence to disk or an external graph database.

================================================================================
2. ACCEPTED DESIGN DECISIONS
================================================================================

1. English-first, deterministic, rule-based MVP.
   Use lexicons, suffix rules, and pattern grammars. No external libraries.

2. Lexical structures remain transient.
   Tokens, chunks, mentions, and frames stay in memory. Only resolved semantic
   mentions become Chain_Node or graph nodes. This keeps lexical and semantic
   layers separate without polluting the knowledge graph.

3. Predicates use the runtime link-type registries.
   Register extracted predicate lemmas as forward and inverse link types with
   the same stable integer ID. Reserve IDs 1-999 for Module 4 ontology
   relations and use IDs 1000 and above for Module 3 lexical predicates.

4. Prefer direct relation links for the MVP.
   "Alice sees Bob" becomes Alice --see/actions--> Bob.
   "Alice works at Acme" becomes Alice --work_at/actions--> Acme.
   Full event-node reification for time, place, and participants is deferred.

5. Assertion-only ingestion initially.
   Negated, hypothetical, and strongly modal statements are parsed and
   reported, but not merged as positive facts until Module 4 adds polarity and
   modality handling.

6. Question chains are oriented around known anchors.
   Response extraction starts from a terminal query node. Build query chains so
   the known entity is terminal where possible. Wh nodes use an empty label and
   an expected semantic type, which enables Module 2 type-only candidates.

7. Session-scoped context and provenance.
   Each NlpPipeline instance owns conversation context and a session provenance
   index. Durable provenance remains a future Module 2/4 extension.

8. No Module 1 or Module 2 model changes are required.
   Use existing node, link, chain, search, trust, and reasoning APIs.

================================================================================
3. CURRENT BASELINE AND INTEGRATION POINTS
================================================================================

Relevant current files:

- OPEN-LRD/LRD_Core.cs
  Owns the graph dictionary, query/response chains, search APIs, connection
  management, maintenance, and label lookup.

- OPEN-LRD/Nodes/Node.cs
  Owns Guid ID, NodeTypes, lifetime, TTL, weight, DataPointer, Label, and
  aliases.

- OPEN-LRD/Nodes/Chain_Node.cs
  Represents a temporary chain node with linkNext and linkPrevious.

- OPEN-LRD/Nodes/Links/Link.cs
  Immutable directed link with SourceID, DestinationID, ForwardLink,
  InverseLink, and Classification.

- OPEN-LRD/Nodes/Links/ForwardLinkTypes.cs, InverseLinkTypes.cs, LinkClass.cs
  Thread-safe runtime registries with stable integer IDs.

- OPEN-LRD/Reasoning/ReasoningEngine.cs
  Facade for Ingest, Answer, and IngestAndAnswer.

- OPEN-LRD/Reasoning/ReasoningTypes.cs
  QueryGraph, SubgraphMatch, GraphPath, ReasoningResult, and related types.

- OPEN-LRD/Reasoning/QueryGraphBuilder.cs
  Converts LinkedList<Chain_Node> into a validated QueryGraph.

- OPEN-LRD/Reasoning/ResponseExtractor.cs
  Extracts ranked response paths and builds response chains.

Integration constraints:

- The Reasoning Engine accepts non-empty LinkedList<Chain_Node> input.
- Query graphs are currently linear; complex facts must be split into multiple
  linear chains.
- Response extraction starts from the terminal query node.
- Link construction rejects unknown forward or inverse link-type IDs.
- NodeTypes currently provides Empties, Basics, Dictionaries, Objects,
  Concepts, Entities, Names, Sources, Locations, Events, and RawData.

Current gaps that Module 3 must account for:

- No tokenizer, POS tagger, parser, NER, or language generation exists.
- No predicate relation vocabulary exists beyond basic link types.
- No pronoun or conversation-context state exists.
- No question classification or answer-template logic exists.
- No durable provenance or lexical storage exists.

6. PIPELINE ALGORITHMS
================================================================================

6.1 Normalization and tokenization

- Normalize Unicode and common typographic characters.
- Split sentences on ., !, ?, and line breaks while protecting abbreviations
  and decimal numbers.
- Tokenize words, numbers, dates, punctuation, hyphenated terms, and
  contractions.
- Preserve exact source spans.
- Enforce MaxCharacters, MaxSentences, and MaxTokens limits.

6.2 POS tagging and lemmatization

- Use lexicon-first tagging for determiners, pronouns, prepositions,
  conjunctions, auxiliaries, wh-words, numbers, and punctuation.
- Apply contextual rules:
  - after determiner or adjective -> noun
  - after modal, auxiliary, or "to" -> verb
  - before noun -> adjective
  - capitalized unknown -> proper noun
  - suffix heuristics for -ed, -ing, -s, -ly, -tion, -ness, and -able
- Use an irregular lemma table plus plural, verb, and comparative rules.

6.3 Shallow parsing

- Build noun phrases from determiners, adjectives, nouns, and proper nouns.
- Build verb groups from auxiliaries, modals, and main verbs.
- Build prepositional phrases from preposition plus noun phrase.
- Detect clause boundaries at coordinating and subordinating conjunctions.
- Classify declarative, yes/no question, wh-question, and imperative input.
- Support simple SVO, SV, copula, possession, and verb plus preposition.

6.4 Named-entity recognition and semantic typing

NodeTypes mapping:

- Person, organization, or unknown proper name -> Entities
- Location or place -> Locations
- Date, time, quantity, or number -> RawData
- Event noun -> Events
- Common noun or concept -> Concepts
- Predicate or verb -> represented as a link type, not a node

Use capitalization, title cues, location cues, date patterns, and small
gazetteers. Avoid large hardcoded encyclopedic lists.

6.5 Entity resolution

- Resolve known mentions through FindByLabel with type filtering.
- Use aliases and prior conversation focus.
- Resolve pronouns by recency, expected type, and number compatibility.
- Return an ambiguity diagnostic when multiple antecedents remain plausible.
- Unknown mentions become new temporary semantic nodes.

6.6 Relation extraction patterns

- Copula: X is Y -> identity link.
- Possession: X has Y -> has relation.
- Intransitive: X runs -> relation or diagnostic as appropriate.
- Transitive: X sees Y -> X --see--> Y.
- Verb plus preposition: X works at Y -> X --work_at--> Y.
- Prepositional location and time -> spatial or temporal classification.
- Coordination -> fan out multiple frames.
- Passive normalization if practical: Y was seen by X -> X --see--> Y.
- Negation and modality -> preserve flags, but do not ingest as positive.
- Unsupported complex patterns -> diagnostics and no merge.

6.7 Chain construction

- Identity: subject --is/identities--> complement.
- Action: subject --predicate/actions--> object.
- Qualifier: emit an additional best-effort chain with spatial or temporal
  classification.
- Use basic link types only for default edges.
- Use registered predicate IDs for extracted relations.
- Set linkNext and linkPrevious on adjacent chain nodes.
- Enforce MaxChainsPerText and MaxClauses.

6.8 Ingestion

- Parse text and extract frames.
- For each supported frame, build a chain and call ReasoningEngine.Ingest.
- Aggregate statuses, diagnostics, promoted nodes, and trust results.
- Record session provenance with source text span, source ID, topic ID, frame,
  and relation link keys.
- Do not mutate permanent knowledge directly.
- Repeated ingestion of the same fact should be idempotent.

6.9 Question analysis

- Classify yes/no and wh-questions.
- Map wh-words to expected NodeTypes:
  - who -> Entities
  - where -> Locations
  - when -> RawData initially
  - what -> Entities or Concepts
  - how many -> RawData
  - why and how -> unsupported diagnostic initially
- Resolve known mentions and pronouns from context.
- Build a query frame with a wh placeholder.
- Orient the chain so a known entity is terminal for response extraction.

6.10 Answer generation

- Use ResponseChain and ResponsePaths to identify the selected fact.
- Extract the answer from SelectedMatch.NodeMap for wh-questions.
- Use ranked response paths for broad questions.
- Generate text with link-aware templates:
  - Identity: X is Y.
  - Action: X predicate Y.
  - Spatial or temporal: append qualifier where available.
  - Fallback: X relation-name Y.
- Add explicit caveats:
  - Provided-source wording when session provenance exists.
  - Stored-knowledge wording for pre-existing graph facts.
  - Candidate list for ambiguous matches.
  - Honest no-match wording.
  - Unsupported negation or hypothetical wording.
- Never fabricate a relation or answer when no path exists.

   - Readable identity, action, and qualifier answers.
   - Source-backed and stored-knowledge wording.
   - Ambiguity and no-match caveats.

================================================================================
9. KNOWN LIMITATIONS
================================================================================

- Rule-based English only; no statistical accuracy guarantees.
- Linear chains only; complex multi-clause and branched facts are split or
  rejected.
- Negation, modality, tense, and hypotheticals are not fully represented in the
  graph initially.
- Direct relation links replace full event reification in the MVP.
- Lexical storage and durable provenance are session-scoped initially.
- Ambiguity is surfaced rather than silently resolved.
- Module 4 will add ontology relations, type hierarchies, and selectional
  restrictions.

================================================================================
10. ACCEPTANCE CRITERIA
================================================================================

- Analyze("Alice works at Acme.") produces tokens, POS tags, mentions, and a
  work_at relation frame.
- Ingest creates temporary nodes and links through Module 2 without direct
